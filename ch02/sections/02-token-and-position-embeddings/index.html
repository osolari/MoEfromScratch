    2.2 Token and position embeddings¶

    Section 2.1 produced \((B, T)\) tensors of integer token IDs. Every downstream module — attention, the dense FFN of Section 2.4, and the MoE replacements in Chapters 3–10 — expects floats, not integers, and expects the decoder interface \((B, T, D)\) that Chapter 1 promised. The embedding step bridges the two. It is also the first place the model width \(D\) from Chapter 1 actually appears.

    Figure 2.2 — Two table lookups, summed. Each integer in input_ids indexes one row of the token table \(E_{\text{tok}}\); the positions \(0, 1, \dots, T{-}1\) index one row of the position table \(E_{\text{pos}}\); the two \((D,)\) vectors are summed elementwise. The position lookup is the only piece of information that distinguishes the same token appearing at two different times. Rendered via TikZ in the PDF version.

                                              ┌──────────────────┐
input_ids (B,T) ─── token IDs ──────────► │  E_tok (V, D)    │
   row 0: [1, 12, 0, 13, 12, 0, 16, 8]    │  lookup per ID   │ ──┐
   row 1: [0,  6, 10, 9,  5, 15, 0, 6]    └──────────────────┘   │
                                                                  ├─►  (+)  ─►  x  (B, T, D)
                positions 0..T-1          ┌──────────────────┐   │
                  (broadcast over batch)  │  E_pos (T_max, D)│ ──┘
                                          │  lookup per t    │
                                          └──────────────────┘
              x[b, t]  =  E_tok[ ids[b, t] ]  +  E_pos[ t ]

    Keep the chapter-2 anchor mini-example: \(B = 2\), \(T = 8\). Section 2.1 produced a \((2, 8)\) input_ids batch with vocabulary size \(V = 19\) from the reference corpus. Pick the model width \(D = 16\) and the maximum context length \(T_{\max} = 8\) (the same as the block size we used for batching), and the two embedding tables hold \(V D + T_{\max} D = 19 \cdot 16 + 8 \cdot 16 = 304 + 128 = 432\) parameters.

    Name the new symbols. We keep \(B\) (batch size), \(T\) (sequence length), and \(V\) (vocab size) from Section 2.1. The model width \(D\) enters the book here for the first time as a live tensor dimension (it was declared in Chapter 1 but no module had it yet). One more constant appears: \(T_{\max}\), the maximum context length the position table supports; a \((B, T)\) batch with \(T \le T_{\max}\) slices into the top \(T\) rows of \(E_{\text{pos}}\).

    Table 2.2 — Tensor and parameter contract for the chapter-2 embeddings. With the reference-corpus vocabulary (\(V=19\)), \(D=16\), \(T_{\max}=8\), the two tables hold \(304 + 128 = 432\) parameters.

    Tensor name Shape Created by Used by Failure check
    token_embed.weight \(E_{\text{tok}}\) \((V, D)\) float nn.Embedding(V, D) Row lookup for every \(\mathrm{input\_ids}_{b,t}\). Backward through a non-zero output assigns gradient to at least the rows of observed token IDs.
    position_embed.weight \(E_{\text{pos}}\) \((T_{\max}, D)\) float nn.Embedding(T_max, D) Row lookup for every position \(t \in \{0,\dots,T-1\}\). A \(T\)-long batch produces non-zero grad on rows \(0..T-1\) and zero grad on rows \(T..T_{\max}-1\).
    input_ids \((B, T)\) long get_batch (Section 2.1) Indexing into \(E_{\text{tok}}\). input_ids.dtype == torch.long; rank \(== 2\); entries \(< V\).
    x (embedded sequence) \((B, T, D)\) float TokenPositionEmbedding(...)(input_ids) Causal self-attention (Section 2.3); decoder block. Falsifiable: x.shape == (B, T, D) and gradients reach BOTH tables on backward.
    Failure mode — dropping either summand — One of the two *.weight.grad tensors is all-zero; the diagnostic fires.

    The forward pass is one tensor equation that names every shape.

    \[ x_{b,t} \;=\; \underbrace{E_{\text{tok}}\bigl[\mathrm{input\_ids}_{b,t}\bigr]}_{\text{token table lookup}} \;+\; \underbrace{E_{\text{pos}}[t]}_{\text{position table lookup}} \;\in\; \mathbb{R}^{D}, \qquad E_{\text{tok}} \in \mathbb{R}^{V \times D}, \;\; E_{\text{pos}} \in \mathbb{R}^{T_{\max} \times D}, \;\; x \in \mathbb{R}^{B \times T \times D}. \]

    The equation packs the entire step into one line, but two details matter. First, the position lookup is shared across the batch: \(E_{\text{pos}}[t]\) depends only on the position index \(t\), not on the row \(b\), so the same \(T\) vectors are added to every row of the batch (broadcast). Second, the sum is the only operator that connects the two tables. Drop one summand and the corresponding table receives no gradient at all — which is exactly what the diagnostic checks.

    The implementation mirrors the equation one line at a time. It lives in src/moe_from_scratch/ch02/embedding.py as TokenPositionEmbedding, an nn.Module whose constructor takes the three sizes (\(V\), \(D\), \(T_{\max}\)) and whose forward returns a \((B, T, D)\) tensor.

    class TokenPositionEmbedding(nn.Module):
    def __init__(self, vocab_size, d_model, context_length):
        super().__init__()
        self.token_embed    = nn.Embedding(vocab_size,     d_model)   # E_tok: (V,     D)
        self.position_embed = nn.Embedding(context_length, d_model)   # E_pos: (T_max, D)
        self.context_length = context_length

    def forward(self, input_ids):                                     # (B, T) long
        T = input_ids.shape[1]
        assert T <= self.context_length
        positions = torch.arange(T, device=input_ids.device)          # (T,)
        return self.token_embed(input_ids) + self.position_embed(positions)  # (B, T, D)

# Mini-example (chapter-2 anchor): V=19, D=16, T=8, B=2.
embed = TokenPositionEmbedding(vocab_size=19, d_model=16, context_length=8)
x     = embed(input_ids)                          # input_ids from get_batch(...)
assert x.shape == (2, 8, 16)
x.sum().backward()
assert embed.token_embed.weight.grad.abs().sum()    > 0
assert embed.position_embed.weight.grad.abs().sum() > 0

    The example script under examples/ch02/ threads the seed-0 batch from Section 2.1 into the module, prints the parameter counts (\(304 + 128 = 432\)), checks the output shape, runs x.sum().backward(), and verifies that both embed.token_embed.weight.grad and embed.position_embed.weight.grad have non-zero \(\ell_1\) norm. With this batch and seed both grads have \(\ell_1\) norm exactly \(256\) (each summand contributes \(B \cdot T = 16\) ones to \(B \cdot T \cdot D = 256\) entries). The pytest suite under tests/ch02/ adds the closed-form check \(x_{b,t} = E_{\text{tok}}[\mathrm{ids}_{b,t}] + E_{\text{pos}}[t]\), asserts that the same token at two different positions produces different embeddings, and verifies that only the rows of \(E_{\text{tok}}\) corresponding to observed token IDs receive non-zero gradient.

    Diagnostic. Assert output shape and confirm gradients flow to both embedding tables. Run python examples/ch02/section_2_2_token_and_position_embeddings.py and verify the printed lines: V=19, D=16, T_max=8; total = 432 parameters; x.shape = (2, 8, 16); \(|\text{token grad}|_1 = 256\) and \(|\text{pos grad}|_1 = 256\). Then pytest tests/ch02/ -q should add at least 12 new tests (ch02 23/23) covering size validation, forward shape, the same-token-different-position contrast, and the row-selective gradient pattern.
