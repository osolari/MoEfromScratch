    2. 2. A dense Transformer baseline from scratch

    2.1 Dataset and token batches¶

    Chapter 1 ended with a contract: MoE will replace the FFN sub-layer of a dense decoder block, keep the \((B, T, D)\) decoder interface, and stay falsifiable at every rung of the ladder. Before the first expert can be wired in, that dense block needs an input to consume. This chapter builds the dense baseline; this section builds its data pipeline. The whole pipeline lives behind one function, get_batch, which returns a \((B, T)\) tensor of input token IDs and a parallel \((B, T)\) tensor of target IDs shifted by one position. Every later model variant in the book — top-1, top-2, shared experts, MiniDeepSeekMoE — consumes batches with exactly these shapes.

    Figure 2.1 — Four stages of the chapter-2 data pipeline: text → tokenized stream → train/val split → random-offset slicing into \((B, T)\) input and target windows. The arrows under the two rows show the one-position shift that makes target[t] equal to input[t+1] on every row. Rendered via TikZ in the PDF version.

    Take the chapter's anchor mini-example: \(B = 2\) samples, \(T = 8\) tokens per sample. We tokenize a short corpus, split tail \(10\%\) for validation, sample two random start offsets from the train half, and slice two parallel windows of length \(T\) at each offset. The reference corpus is deliberately written from cat, sat, code, runs (the four words from Section 1.3) so the reader can carry the same vocabulary across chapters.

    Name the new symbols before writing the equation. We keep \(B\) (batch size) and \(T\) (sequence length, also called the block size) from Chapter 1. Two new constants enter the book here: \(V\), the vocabulary size — the number of distinct token IDs the tokenizer emits, used as the row count of the embedding matrix in Section 2.2 and the column count of the language-model head; and \(N_{\text{tokens}} = N_{\text{train}} + N_{\text{val}}\), the length of the token stream after splitting. The model width \(D\) from Chapter 1 has not appeared yet — it enters at the embedding step.

    Table 2.1 — Tensor contract for the chapter-2 data pipeline. Every later model variant consumes batches with exactly these shapes.

    Tensor name Shape Created by Used by Failure check
    tokens \((N_{\text{tokens}},)\) long tokenizer.encode(text) make_split (train / val), get_batch tokens.dtype == torch.long; all IDs \(< V\).
    train, val \((N_{\text{train}},)\), \((N_{\text{val}},)\) long make_split(text, val_fraction) get_batch \(N_{\text{train}} + N_{\text{val}} = N_{\text{tokens}}\); both non-zero.
    input_ids \((B, T)\) long get_batch(train, B, T) Section 2.2 embeddings Each row decodes to a contiguous slice of the source text.
    target_ids \((B, T)\) long get_batch(train, B, T) Next-token cross-entropy loss (Section 2.5) Falsifiable: target[:, :-1] == input[:, 1:].
    Failure mode — reuse same start offset for input/target — Loss becomes trivial (predict the token you already saw); shift check fires.

    The next-token objective is purely an indexing relation between two slices of the same stream.

    \[ \mathrm{input}_{b,t} \;=\; \mathtt{tokens}[s_b + t], \qquad \mathrm{target}_{b,t} \;=\; \mathtt{tokens}[s_b + t + 1], \qquad\text{so}\qquad \boxed{\;\mathrm{target}_{b,t} \;=\; \mathrm{input}_{b,t+1}\;} \quad\text{for } t \in \{0,1,\dots,T{-}2\}. \]

    The equation says exactly one thing: input and target are slices of the same token stream that differ by a single position. The boxed identity target[t] == input[t+1] for \(t \in \{0, \dots, T{-}2\}\) is the section's falsifiable diagnostic. Break the +1 on the target slice — accidentally pass the same start offset for both — and the identity fails on every row.

    The listing realises the equation in seven lines of PyTorch. It mirrors src/moe_from_scratch/ch02/dataset.py exactly, including the function name get_batch and the keyword-only generator parameter we use to make the example script reproducible.

    def get_batch(tokens, *, batch_size, block_size, generator=None):
    # tokens: (N_tokens,) long stream from make_split(text).train.
    n = tokens.shape[0]
    high = n - block_size
    starts = torch.randint(0, high, (batch_size,), generator=generator)
    input_ids  = torch.stack([tokens[s     : s + block_size    ] for s in starts])
    target_ids = torch.stack([tokens[s + 1 : s + 1 + block_size] for s in starts])
    return input_ids, target_ids       # both (B, T)

# Mini-example: B=2, T=8 over the chapter-2 reference corpus (cat, sat, code, runs).
split = make_split(REFERENCE_CORPUS, val_fraction=0.1)
gen   = torch.Generator().manual_seed(0)
x, y  = get_batch(split.train, batch_size=2, block_size=8, generator=gen)
assert torch.equal(y[:, :-1], x[:, 1:])   # target[:, t] == input[:, t+1]

    Running the example script under examples/ch02/ on the reference corpus prints a 19-character vocabulary, 162 train tokens, 18 val tokens, and then a \((2, 8)\) batch. With seed \(0\) the first input row decodes to "an on th" and the corresponding target row decodes to "n on the" — the target is the input shifted left by one character, which is exactly what the equation promises. The final assert in the script checks the shift identity on both rows of the batch at once via torch.equal(target[:, :-1], input[:, 1:]); the pytest suite under tests/ch02/ adds an independent random-seed check and rejects bad inputs (zero block_size, 2-D tokens, etc.).
