    2. 2. A dense Transformer baseline from scratch

    2.4 Dense feed-forward block as the replacement target¶

    Section 2.3 mixed positions across the sequence; what is left in a decoder layer is the per-token transformation that runs after attention. That block is the dense FFN of Section 1.1 — the same class, the same constructor signature DenseFFN(d_model, hidden), the same \(2 D H\) parameter count. Chapter 1 already counted what it costs; this section installs it inside the chapter-2 baseline and frames it as the replacement target. Every MoE variant the rest of the book builds is a drop-in substitute for this object.

    Figure 2.4 — The skeleton that survives unchanged into Chapter 3. Today (top row) a single DenseFFN sits between a \((B, T, D) \to (B \cdot T, D)\) flatten and the inverse unflatten; tomorrow (bottom row) the same skeleton wraps a bank of expert FFNs with \(K\) chosen per token. The \((B, T, D)\) tensor on either end of the skeleton does not move. Rendered via TikZ in the PDF version.

    today:   x (B,T,D)  ──flatten──►  (B·T, D)  ──► [ DenseFFN: W1 (D,H), W2 (H,D), GELU ] ──►  (B·T, D)  ──unflatten──►  y (B,T,D)

Ch.3:    x (B,T,D)  ──flatten──►  (B·T, D)  ──► [ Expert 1 ]                                  (B·T, D)  ──unflatten──►  y (B,T,D)
                                              │ [ Expert 2 ]  ◄── router picks K per token  ▲
                                              │     ...                                       │
                                              └─► [ Expert E ] ─────────────────────────────► ┘

         same skeleton; only the per-token transformation changes when MoE replaces DenseFFN.

    Take the chapter-2 anchor mini-example: \(B = 2\), \(T = 8\), \(D = 16\). Pick \(H = 4 D = 64\), the standard expansion factor used throughout the book. The block stores \(2 D H = 2048\) parameters and spends \(2 D H = 2048\) multiply-adds per token, which is the cost we counted in Section 1.1 — nothing has changed except where the module lives. For the full \(B \cdot T = 16\) tokens of the anchor batch the dense FFN charges \(2 N D H = 32{,}768\) multiply-adds.

    Name the new symbols. We keep \(B, T, D, H, N\) from Section 1.1. The only new objects here are the two helper functions: flatten_tokens(x) returns the \((B \cdot T, D)\) view of \(x\) along with the \((B, T)\) tuple needed to restore the shape, and unflatten_tokens(flat, (B, T)) is its inverse. We will use this pair literally unchanged when Chapter 6 vectorises dispatch.

    Table 2.4 — What the dense FFN provides today and what each piece becomes when Chapter 3 replaces it with an MoE layer. Same shape, same per-token semantics; the only thing that changes is how the experts are selected.

    Concept (today) Shape What it does Replacement in Chapter 3
    \(x\) (input) \((B, T, D)\) Output of attention + residual; the decoder interface invariant from Chapter 1. Unchanged.
    \(W_1\) (up-projection) \((D, H)\) Single, shared up-projection for every token. Becomes \(E\) per-expert up-projections; each token uses \(K\) of them.
    \(W_2\) (down-projection) \((H, D)\) Single, shared down-projection for every token. Becomes \(E\) per-expert down-projections, weighted by router gates.
    flatten_tokens(x) \((B \cdot T, D)\) Row-major reshape; identity on the per-token view of the FFN. Section 6.1 uses this exact reshape as the dispatch unit.
    Per-token equivalence — \(\mathrm{DenseFFN}(x) = \mathrm{unflatten}(\mathrm{DenseFFN}(\mathrm{flatten}(x)))\). MoE preserves the equivalence per-token, but the function varies by token.
    Parameters (anchor) \(2DH = 2048\) \(D=16\), \(H=64\). Block totals (embed/attn/FFN): \(304 + 128 + 1024 + 2048 = 3504\). Bank: \(E \cdot 2 D H\) total; activated per token: still \(K \cdot 2 D H\).
    Diagnostic \((B, T, D) \to (B, T, D)\) Falsifiable: output shape equals input shape, AND \(\mathrm{DenseFFN}(x)\) is byte-identical to \(\mathrm{unflatten}(\mathrm{DenseFFN}(\mathrm{flatten}(x)))\). The same two checks survive into the MoE layer.

    The block is one tensor equation written per-token.

    \[ \mathrm{DenseFFN}(x)_{b,t} \;=\; \mathrm{GELU}\bigl(x_{b,t}\, W_1\bigr)\, W_2, \qquad W_1 \in \mathbb{R}^{D \times H}, \;\; W_2 \in \mathbb{R}^{H \times D}, \;\; x \in \mathbb{R}^{B \times T \times D} \;\;\text{(per-token; no cross-token mixing)}. \]

    The equation reads carefully: the subscript \((b, t)\) on the left and the right makes the per-token structure explicit. The right-hand side never indexes another row of the batch and never indexes another position in the sequence. Cross-token mixing is the job of attention; the FFN sub-layer is purely a token-wise non-linearity. That is the property the MoE replacement preserves — the per-token transformation can change from token to token, but the transformation is still per-token.

    The listing re-exports DenseFFN from Chapter 1 (the constructor signature is locked by Section 1.6) and adds the flatten / unflatten pair.

    # Re-export the locked-in Chapter-1 module. Same signature: DenseFFN(d_model, hidden).
from moe_from_scratch.ch01 import DenseFFN, dense_ffn_cost

def flatten_tokens(x):                            # (B, T, D) -> (B*T, D)
    B, T, D = x.shape
    return x.reshape(B * T, D), (B, T)

def unflatten_tokens(flat, bt):                   # (B*T, *) -> (B, T, *)
    B, T = bt
    return flat.reshape(B, T, flat.shape[-1])

# Mini-example: chapter-2 anchor (B=2, T=8, D=16) + H=64.
ffn       = DenseFFN(d_model=16, hidden=64)
y_direct  = ffn(x_mixed)                          # (2, 8, 16) from attention
flat, bt  = flatten_tokens(x_mixed)
y_via_flat = unflatten_tokens(ffn(flat), bt)

# Diagnostic (falsifiable):
assert y_direct.shape == (2, 8, 16)               # (B, T, D) interface holds
assert torch.equal(y_direct, y_via_flat)          # FFN is exactly per-token
assert sum(p.numel() for p in ffn.parameters()) == 2 * 16 * 64 == 2048

    The example script under examples/ch02/ threads the seed-0 anchor batch through embed → attention → dense FFN, prints the parameter count, and verifies two things at once: the output shape is exactly \((B, T, D)\), and the FFN output is byte-identical whether the input is given as a \((B, T, D)\) tensor or as a flattened \((B \cdot T, D)\) tensor followed by an unflatten. That equality is the strongest possible test of "per-token" — any cross-token mixing inside the block, intentional or accidental, breaks it.
