    1.6 Chapter summary and handoff¶

    Section 1.5 named the destination — MiniDeepSeekMoE-16x2 — and the twelve-rung path to it. Before climbing, take stock: Chapter 1 introduced fifteen symbols, four skeleton classes, two configurations, a twelve-rung build ladder, and one decoder-interface invariant. The risk now is that any of that drifts as the implementation gets bigger. This section closes the chapter by writing the vocabulary down in one place, locking the skeleton constructors with a runtime signature check, and answering the question that determines whether the build ladder is well-posed at all: which part of the dense decoder block are we actually replacing?

    Figure 1.6 is the chapter on one page: tokens enter on the left, the router–top-\(K\)–softmax pipeline lives in the middle, the output exits on the right, and a side panel names what stays the same (residual, attention, \((B,T,D)\) interface) and what gets replaced (the dense FFN, and only that). The four-token example from Section 1.3 carries every symbol the rest of the book needs. With \(N = 4\) tokens, \(E = 4\) experts, and \(K = 2\), that example produced a score tensor \(s\) of shape \((N, E) = (4, 4)\), an index set \(\mathcal{T}_t\) of shape \((N, K) = (4, 2)\), a gate tensor \(g\) of shape \((N, K) = (4, 2)\) with rows summing to one, and an output tensor of shape \((N, D) = (4, 4)\) that — because the experts were one-hot — literally read out the gate matrix. Chapters 2–10 will replace each of those tensors with a real computation, but the symbols and shapes will not move.

    The shape pipeline of the layer fits in one equation.

    \[ \underbrace{x}_{(B,T,D)} \;\xrightarrow{\text{Router}}\; \underbrace{s}_{(N,E)} \;\xrightarrow{\operatorname{top}K}\; \underbrace{\mathcal{T}}_{(N,K)} \;\xrightarrow{\operatorname{softmax}}\; \underbrace{g}_{(N,K)} \;\xrightarrow{\sum g_{t,i}\,\mathrm{expert}_i(x_t)}\; \underbrace{y}_{(B,T,D)}, \quad N = B\,T,\;\; \mathcal{T}_t \subset \{1,\dots,E\},\;\; \textstyle\sum_{i\in\mathcal{T}_t} g_{t,i} = 1 . \]

    The equation reads left-to-right: tokens \(x\) go into the router and become scores \(s\); top-\(K\) selects an index set \(\mathcal{T}\); softmax over the selected entries produces gates \(g\); the weighted combine of expert outputs lands at \(y\), of the same shape as \(x\). Every arrow is the title of a section we have already seen.

    The chapter is held together by two pieces of code. The first locks the constructors of the four skeleton classes so that later chapters cannot quietly change the contract; the second answers the reader checkpoint by walking the decoder paths and asserting that only one is replaced.

    def required_signatures():
    # Lock the constructor signatures every later chapter must keep.
    return {
        Router:          ("self", "d_model", "n_experts"),
        ExpertMLP:       ("self", "d_model", "hidden"),
        MoELayer:        ("self", "d_model", "hidden", "n_experts", "top_k"),
        MiniDeepSeekMoE: ("self", "d_model", "hidden", "n_experts", "top_k", "n_shared"),
    }

def check_signatures():
    for cls, expected in required_signatures().items():
        actual = tuple(inspect.signature(cls.__init__).parameters.keys())
        if actual != expected:
            raise AssertionError(f"{cls.__name__} drifted: {actual} != {expected}")

def moe_replaces_only_ffn():
    # Reader checkpoint: residual and attention stay; the FFN is what swaps.
    replaced = [p for p in decoder_replacement_plan() if p.replaced_by_moe]
    return len(replaced) == 1 and replaced[0].path == "FFN"

check_signatures()                # locked-in API survives
assert moe_replaces_only_ffn()    # the (B,T,D) interface is preserved by Ch.2-10

    The signature check uses inspect.signature on Router.__init__, ExpertMLP.__init__, MoELayer.__init__, and MiniDeepSeekMoE.__init__ and raises AssertionError on any drift. The replacement check returns True when exactly one decoder path is marked replaced and that path is the FFN; if a future chapter ever marks attention or the residual as replaceable, the predicate will fail and the diagnostic will catch the contradiction with the chapter-level invariant.
